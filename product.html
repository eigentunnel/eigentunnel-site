Product

One overlay. Two ways to run it.

EigenTunnel Core does the cryptographic work: it cloaks enrolled nodes and protects data in flight with hybrid post-quantum key exchange and signatures. EigenTunnel Cloud sits on top and handles everything a fleet needs that a single node can't do for itself.

Cryptography

Protect traffic with a long shelf life.

Harvest-now-decrypt-later is the primary threat model: an adversary records ciphertext today and decrypts it once a cryptographically-relevant quantum computer exists. Anything that needs to stay confidential for years — not days — is exposed under classical-only crypto right now.

Hybrid tunnels

X25519 + ML-KEM-768 (FIPS 203) key establishment. AES-256-GCM or ChaCha20-Poly1305 for bulk encryption. Classical and post-quantum components are combined, so the session stays safe even if one primitive is later broken.

Mutual authentication

ML-DSA-65 (FIPS 204) signatures. No session is established unless the peer proves a registered identity — there is no anonymous listener mode.

Cryptographic agility

Parameter sets and algorithms can move forward as NIST and industry standards evolve. Forward secrecy is per-session, so compromising one session key doesn't unwind history.

Connectivity

Connect when the network will not cooperate.

Two paths, same cryptography underneath.

Direct: Node A -> EigenTunnel overlay -> Node B
Relay:  Node A --outbound only--> gateway <--outbound only-- Node B

When a direct path exists, nodes connect over the overlay directly. When NAT, CGNAT, or a restrictive network gets in the way, the gateway relay accepts leaf sessions only — it never dials your phone, your Starlink home connection, or a hotel laptop. Both endpoints reach out to the gateway; the gateway never reaches in.
