About

Eigen Systems builds EigenTunnel.

We're building a post-quantum protected-path company with a careful split: public lab review where it helps trust, private Core and Cloud where the product value lives.

Why the name changed

Previously FreeQ. Now EigenTunnel.

This product was previously marketed as FreeQ. That name collided with an unrelated influencer's site, so the product name, repositories, and domain moved to EigenTunnel. Older references may still exist in private history and internal artifacts; new public work should use EigenTunnel.

Why now

Harvest-now-decrypt-later is not hypothetical.

Traffic encrypted with classical-only key exchange today can be recorded now and decrypted later, once large-scale quantum computers exist. For data with a multi-year confidentiality requirement — infrastructure telemetry, credentials, long-lived secrets — that clock is already running. EigenTunnel exists so teams can start hybrid PQC migration on real traffic paths now, without waiting for a mandate.

Integration-first

Designed to sit alongside systems of record: IdP, CMDB, ITSM, SIEM, and existing operational workflows.

Evidence, not slogans

CBOM and OSCAL-oriented work should be grounded in approved-scope discovery, reproducible outputs, and explicit limits.

Public trust, private value

Public Python tools support lab review; Core software source remains private. The implemented private cnsa2 profile is a paid Core/Cloud capability. CBOM is a prototype, OSCAL drafts are available on request, and relay/gateway connectivity is founder-tested, Cloud payment and provisioning are unfinished, and fleet workflows remain roadmap.
